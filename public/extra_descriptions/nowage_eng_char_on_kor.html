What it does

In Korean input mode, typing a few English characters normally means a round trip: switch to English, type, switch back. This rule removes the round trip. While Insert is held the input source is English; when you release it, Korean comes back. No mode is left behind.

ActionResult
Hold Insert, type lettersEnglish, as many characters as you like (a p i → api)
Hold Insert, tap HomeToggle capitals on/off — following letters stay uppercase
Hold Insert, shift+letterA single capital (still works)
Release InsertBack to Korean; the capital toggle is reset
Insert in English modeRule does not fire — Insert keeps its normal behaviour
Home outside the layerRule does not fire — Home keeps its normal behaviour

한국어 요약

이 규칙을 쓸 사람은 대부분 한국어 입력기 사용자이므로 요약을 한글로도 적는다. (This section repeats the above in Korean, for the users this rule is aimed at.)

한글 입력 중 영문 몇 글자를 치려고 한/영 전환 → 입력 → 한/영 전환을 왕복하는 대신, Insert 를 누르고 있는 동안만 영문이 나간다. 손을 떼면 한글로 돌아오며 모드가 남지 않는다. 레이어 안에서 Home 을 탭하면 대문자가 토글되고, 레이어 밖 Insert·Home 은 평소대로 동작한다. 전환 단축키가 ⇧space 든 무엇이든 무관하다 — 이 규칙은 입력소스를 직접 지정하지 단축키를 흉내내지 않는다.

Requirements

No hardware and no external application is required. What the rule does need:

#Requirement
A A physical key that actually sends insert, not claimed by another rule. Which physical key emits insert differs between keyboards — check in Karabiner-EventViewer first. On keyboards without one, change from.key_code before importing.
B Home must be free while the layer is active. Outside the layer Home is untouched — the rule borrows it with a variable_if condition instead of taking it away, so no key is permanently spent.
C Korean and English input sources identifiable as ^ko$ / ^en$ (the macOS defaults).
D A Hangul IME that commits the composing syllable when it receives a space — the standard behaviour of the macOS Korean input sources.

Your Korean/English switching shortcut does not matter. The rule changes the input source with select_input_source, it never sends a switching shortcut, and the layer key consumes modifiers (mandatory: ["any"]) so nothing leaks onto the keys it emits.

Why a composing syllable would otherwise be lost

Hangul commits a syllable only when the next initial consonant arrives. If the input source is changed while a syllable is still composing, the IME discards it instead of committing — type 아 and switch, and the 아 is gone.

So the rule sends space and delete_or_backspace immediately before switching: the space forces the commit, the backspace removes the space itself. Karabiner has no condition for "IME is composing", so this is done unconditionally.

Variables

Two variables are set: keyboardLayoutSettingIsEng (1 while the layer is active) and engCharUpper (1 while capitals are toggled on). Both are reset when Insert is released. If you already use a variable with either name, rename it in the JSON before importing.

Source and documentation

This rule is maintained in the open, together with four other rules by the same author: Finfra/karabiner-extensions — EngCharOnKor. The repository records why Insert was chosen over six other candidate triggers, and why the capital toggle uses a variable rather than sticky_modifier — useful if you want to move the layer to a different key.
